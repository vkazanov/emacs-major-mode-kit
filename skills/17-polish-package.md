# Skill: Polish Package

## Goal

Perform the final package-quality pass for a generated mode so it is consolidated,
consistent, loadable, byte-compilable, documented, and free of unexpected load-time
side effects.

## When to use

Use after applying all feature skills needed for the generated mode. This is a final
review and cleanup step, not a place to add new editing, navigation, tree-sitter,
diagnostic, run, or format behavior.

This skill is mandatory final wrap-up for generated modes. Apply it even when the
requested feature range stops before skill `17`.

## Allowed files

- Generated mode file.
- Optional generated tree-sitter mode file.
- Generated test file.
- Temporary generated facts file.
- Sample files used by tests.
- Generated package documentation when the mode already has package-local docs.

Do not edit repository-level templates, shared validation machinery, or unrelated
examples while polishing a generated package.

- `checkdoc-current-buffer`
- `lm-verify`

- `lm-commentary`
- `lm-code-start`
- `batch-byte-compile`
- `ert-run-tests-batch-and-exit`

- `provide`
- `featurep`
- `boundp`
- `fboundp`
- `lookup-key`
- `where-is-internal`
- `plist-get`

## Requirements

- Keep every Emacs Lisp file using lexical binding.
- Ensure package headers have a one-line summary, `Keywords`, and
  `Package-Requires` with only built-in Emacs requirements.
- Ensure each Lisp file has `;;; Commentary:`, `;;; Code:`, a matching `provide`, and
  a correct file footer.
- Keep the main mode's `define-derived-mode` autoloaded.
- Keep file-extension registration autoloaded and limited to the main regex/basic
  mode unless a user explicitly requested tree-sitter to be the default.
- Ensure optional `LANG-ts-mode` stays separate and opt-in unless that policy was
  explicitly changed in the package.
- Ensure `defgroup` names, docstrings, and parent groups are coherent.
- Ensure `defcustom` forms have useful docstrings, appropriate `:type` values, and
  safe predicates when practical.
- Verify public commands are interactive only when they are intended for users.
- Verify keybindings are installed only in mode-local keymaps.
- Verify load-time code does not run external tools, start processes, install hooks
  globally, enable minor modes globally, create parsers without grammar checks, or
  mutate global state except the autoloaded `auto-mode-alist` registration.
- Verify the package does not use advice.
- Inline the accumulated `LANG-facts` constant into `LANG-mode.el` and remove the
  separate runtime `LANG-facts.el` file.
- Remove `(require 'LANG-facts)` from generated mode files. When `LANG-ts-mode.el`
  exists, it should access inlined facts by requiring `LANG-mode`.
- Keep existing facts-driven helpers such as `(plist-get LANG-facts :keywords)` unless
  a smaller local cleanup is needed for byte compilation.
- Do not introduce code generation, external schema files, or a new runtime data file
  to replace `LANG-facts.el`.
- Ensure every behavior introduced by the applied skills has an ERT test or a clear
  reason it can only be covered by byte compilation or manual grammar/tool smoke
  testing.

## Steps

1. List the generated package files and identify whether an optional `LANG-ts-mode.el`
   exists.
2. Move the complete `defconst LANG-facts` form from `LANG-facts.el` into the
   `;;;; Language data` section of `LANG-mode.el`, before any constants that read it.
3. Remove `(require 'LANG-facts)` from `LANG-mode.el` and any optional
   `LANG-ts-mode.el`. Keep `(require 'LANG-mode)` in `LANG-ts-mode.el`.
4. Delete the generated `LANG-facts.el` file after confirming no generated file
   requires it.
5. Review headers, lexical binding, Commentary, Code markers, `provide` forms, and
   footers for every generated Lisp file.
6. Review `defgroup`, `defcustom`, public command, and keymap definitions for naming,
   docstrings, local scope, and customization metadata.
7. Review autoload cookies on `define-derived-mode` and the main mode's
   `auto-mode-alist` registration.
8. Search the generated files for stale facts-file requires, `advice-add`, global
   hooks, global key definitions, process creation on load, and other load-time side
   effects.
9. Run or document `checkdoc-current-buffer` and `lm-verify` findings for each
   generated Lisp file, fixing only issues that are appropriate for the generated
   package.
10. Review tests against the features actually applied and add focused ERT coverage for
   missing public behavior.
11. Byte-compile the main mode and any optional generated Lisp files, including
   `LANG-ts-mode.el` when present.
12. Run validation and clean generated byte-code files before considering the package
   polished.

## Tests

- Run the generated package ERT suite with the repository validation command.
- Assert or manually verify that loading `LANG-mode` does not require a separate
  `LANG-facts` feature after final polish.
- Add missing ERT tests for package-visible behavior, such as mode activation,
  autoloaded file association, mode-local keybindings, command error paths, and
  optional tree-sitter no-op behavior.
- Assert commands that depend on external tools handle missing tools without running
  anything at load time.
- Assert optional mode-local keybindings are visible in `LANG-mode-map` and are not
  globally bound.
- When `LANG-ts-mode.el` exists, keep tree-sitter tests grammar-independent by
  stubbing readiness and setup functions, and guard real-grammar smoke tests with
  `ert-skip`.

## Anti-patterns

- Adding new feature behavior during polish.
- Rewriting already-working feature implementations for style alone.
- Adding external package dependencies, including package-lint.
- Treating checkdoc or lisp-mnt suggestions as permission for broad unrelated edits.
- Registering global keybindings or adding global hooks.
- Adding advice.
- Leaving `(require 'LANG-facts)`, `(provide 'LANG-facts)`, or a tracked
  `LANG-facts.el` runtime file in the final generated package.
- Running compilers, formatters, language servers, tree-sitter grammar installation,
  or other external tools when the package loads.
- Leaving `.elc` files behind after validation.

## Validation

```sh
make test MODE_DIR=path/to/mode MODE=foo
make compile MODE_DIR=path/to/mode MODE=foo
emacs -Q --batch -L path/to/mode -f batch-byte-compile path/to/mode/foo-ts-mode.el
make clean
```

Skip the explicit `foo-ts-mode.el` byte-compilation command when the generated package
does not include a tree-sitter mode.

Expected result: all ERT tests pass, every generated Lisp file byte-compiles, package
metadata checks have been reviewed, no separate runtime facts file remains, no
unexpected load-time side effects remain, and no generated `.elc` files remain after
cleanup.
